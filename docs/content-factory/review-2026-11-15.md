# Content Factory review — 2026-11-15

Scope: local MCP server/service/worker, new motion adapters, and read-only checks
on the Mac mini. No production jobs submitted, credentials printed, or fixes
applied. This is not a complete security audit of every provider adapter.

## Confirmed findings

1. **High — new integrations are not deployed to the connected host.** SSH checks
   found no `lib/motion_scene.py`, `motion-runtime/package.json`, or
   `tools/graphics/motion_scene.py` in the Mac mini checkout. Live MCP discovery
   for `motion_scene` returned zero operations. Local passing tests did not
   establish deployment. Deploy a versioned release, install pinned dependencies,
   build the bundle, and verify live discovery before calling it available.

2. **High — download bearer tickets are logged.**
   `content_factory/remote.py:83` logs the complete `scope['path']`.
   DownloadSigner places its bearer ticket in `/download/{ticket}`, so download
   requests disclose the working five-minute ticket to request logs. This follows
   directly from the two code paths; no real ticket was printed during review.
   Redact that path to `/download/[redacted]` in middleware and check upstream
   access logging as well. This is exposure to log readers, not unauthenticated
   access without a ticket.

3. **Medium — customer profile and history pagination skip records.**
   `content_factory/service.py:73` applies SQL LIMIT/OFFSET, then line 76 applies
   `paginate` to the already-paged list. History repeats this at lines 90–95.
   Reproduced with four temporary profiles: offset=0, limit=2 returns two;
   offset=2, limit=2 returns zero although total=4. Return the SQL page directly.

4. **Medium — renderer health can claim availability with a missing browser.**
   Lemo `get_status` only checks commands, package directories and versions.
   Reproduced with PLAYWRIGHT_CHROME=/definitely/missing/browser: available.
   `motion-runtime/health.mjs` similarly accepts an allowed browser channel name
   without checking installation or launch. Add an explicit executable check and
   a bounded cached launch probe; distinguish dependency readiness from GPU and
   per-scene validation. The Mac mini's two original renderer checks currently
   pass, so this is a future failure-detection defect, not recurrence of PATH loss.

5. **Medium — scene validation accepts broken Lottie payloads.**
   `lib/motion_scene.py:78` checks key presence but not types/ranges. Reproduced
   acceptance of layers=null, fr=0, op=-1, w=-1 and h='bad'. This gets through
   the small-model repair interface and fails later in browser execution.
   Validate layer shape, positive dimensions/frame rate and ordered frame bounds;
   bound nested complexity and return field-specific errors before queueing.

6. **Medium — preview re-runs retain obsolete files and reports.**
   `motion-runtime/render.mjs:6` reuses the output directory; lines 17–20 overwrite
   only current filenames and write a report only on success. A shorter rerun
   leaves former sampled PNGs; a failed rerun can leave the old success report.
   Factory outputs lists those stale files without version discrimination.
   Render to a fresh versioned directory and publish a manifest atomically.

## Coverage gaps

The render fixtures test same-page backward seek, not independent-process or
cross-platform determinism. Text overflow checks only data-label HTML elements,
not SVG diagram labels or chart labels. Approval evidence is caller-supplied
text and depends on the trusted agent not fabricating it, as documented. Native
adapters and authored workspaces are trusted code, not a multi-tenant sandbox.
Do not present these existing trust assumptions as stronger security guarantees.

Recommended order: deployment parity and ticket redaction, pagination, health
probes, then payload validation and atomic preview outputs. Add regression cases
for each before deployment. Model-specific end-to-end evaluation remains undone.

## Test result

Full `tests/content_factory` run: **36 passed, 1 failed** in 65.30s.
`test_scoped_media_download` changed the final ticket character and received
200 instead of 404. The decoder in `DownloadSigner.verify` accepts non-canonical
Base64 representations; unused final bits can change while decoded bytes remain
the same. Therefore this test does not always change signed bytes. This is not
evidence of HMAC forgery. Require canonical encoding if all textual mutations
must fail; separately test mutation of decoded payload/signature bytes.

## Fix implementation

Implemented canonical download-ticket decoding, redacted request paths and disabled
Uvicorn access logging, corrected SQL-backed pagination, added real browser launch
probes, rejected invalid Lottie header/layer types and excessive nesting, and
versioned preview directories with atomic current-attempt status. Added six focused
regression tests. Deployed the motion runtime, schema, adapters, pinned npm/OTIO
dependencies and pipeline permissions to the Mac mini. Original host files are
backed up under `.runtime/backups/review-20261115/pre-fix.tgz` on that host.

## Post-fix verification

Full local suite: **43 passed** using the installed Chrome channel. Mac mini:
**22 targeted tests passed**, covering all motion recipes, MP4 rendering, timeline
export and review regressions. The pinned Chromium installation also passes the
runtime's launch probe. Both MCP processes were restarted; the connected endpoint
reports `lemo:render`, `video_compose`, `motion_scene` and `timeline_export` available.
The coverage gaps above remain explicit limitations, not claims of tested support.
